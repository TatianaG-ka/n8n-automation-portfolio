# Workflow JSON files

Three n8n workflows that constitute the Email Triage System. Files have been **sanitized for public publication** — see [Sanitization](#sanitization) section below.

## Files

| File | Trigger | Nodes | Purpose |
|---|---|---|---|
| [`01-email-triage-main.json`](01-email-triage-main.json) | Gmail polling (1 min) | 33 | Main classification + routing flow |
| [`02-email-triage-extended.json`](02-email-triage-extended.json) | Webhook from main | 24 | AI tasks → Trello + Drive + Approval |
| [`03-email-triage-error-handler.json`](03-email-triage-error-handler.json) | n8n Error Trigger | 5 | Severity-classified Slack + Gmail alerts |

For step-by-step deployment instructions (n8n credentials setup, Google Sheets schema, Slack app creation, OpenAI/Trello configuration, first-test procedure, troubleshooting): see [`docs/SETUP.md`](../docs/SETUP.md).

### Import order

The Error Handler must exist before the others, because Main and Extended reference it via `errorWorkflow` setting:

1. First: `03-email-triage-error-handler.json`
2. Then: `01-email-triage-main.json`
3. Then: `02-email-triage-extended.json`

Full import procedure with credential mapping: [`docs/SETUP.md` Phase 7](../docs/SETUP.md#phase-7--import-workflows).

## Sanitization

These JSON files have been processed before publication to remove personally identifiable information and operational identifiers from the production environment.

### What was sanitized

| Category | What | Replaced with |
|---|---|---|
| Personal email | Admin email address | `your-admin@example.com` |
| Personal name in identifiers | Slack channel name containing first name | `your-slack-channel-name` |
| OAuth credential names | Per-service credential names (e.g., "Gmail OAuth_<personal_account>") | `<Service> OAuth - REPLACE_AFTER_IMPORT` |
| OAuth credential IDs | n8n internal credential references | `CRED_ID_REPLACE_AFTER_IMPORT_N` |
| Workflow IDs | n8n internal workflow IDs | `WORKFLOW_ID_<ROLE>` |
| Webhook IDs | UUIDs for webhook resume + Slack/Gmail webhooks | Sequential placeholders `00000000-0000-0000-0000-NNNN` |
| Google Sheet ID | Real spreadsheet ID linking to client data | `YOUR_GOOGLE_SHEET_ID` |
| Trello list ID | Real list ID in production board | `YOUR_TRELLO_LIST_ID` |
| n8n instance ID | Hostinger instance fingerprint | `REPLACE_AFTER_IMPORT` |
| Internal versionIds | n8n auto-generated version markers | Sequential placeholders |

### What was NOT in the file in the first place

For transparency about what n8n exports and what it does NOT export:

- **OAuth refresh tokens** — n8n stores credentials separately from workflow JSON. No tokens were ever in these files.
- **API keys** (OpenAI, Trello) — same, stored separately.
- **Slack bot tokens** — same.
- **Email content from past executions** — stored in n8n execution logs, not in workflow definition.

Credential references in JSON are pointers (`id` + `name`) to credentials stored in n8n's separate credential store, never the credentials themselves. **Sanitization here is about removing operational fingerprints, not about hiding secrets.**

### What is the same as production

Everything that defines *how the workflow works* is preserved verbatim:

- All node configurations (parameters, settings, retry policies, onError handlers)
- All connections between nodes
- All Code node bodies (JavaScript code, including comments in Polish)
- All AI prompts, structured output schemas, LangChain chain configurations
- All retry strategies, timeouts, error handling

Importing these files produces a workflow that is **structurally identical** to production. The differences are only at the configuration boundary (credentials, webhook URLs) which n8n re-configures on import anyway.

## Verification

After completing setup per [`docs/SETUP.md`](../docs/SETUP.md), run the test suite from [`../test_emails.json`](../test_emails.json) to verify behavior matches the documented production baseline ([`../docs/testy/test_results_2026-04-08.md`](../docs/testy/test_results_2026-04-08.md)).

If any of the 24 tests fail, the most likely cause is incomplete configuration (missing credential, wrong Sheet ID, wrong channel name). The Error Handler workflow surfaces the specific failure with severity classification.
